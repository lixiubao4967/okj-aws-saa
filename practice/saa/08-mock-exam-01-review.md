## 逐题错因

### 错题 16｜Q4：Spot 的唯一识别信号

### 错题 17｜Q8：Intelligent-Tiering 是给「未知」用的
**选 B（Intelligent-Tiering）→ 正确 D（生命周期策略）**
题干首句「使用模式非常明确」，还列了 30 天/90 天/7 年。
**模式已知 → 生命周期策略；模式未知 → Intelligent-Tiering**（后者还多收监控费）。
→ cheatsheet 成本母题②

### 错题 18｜Q10：两个痛点只解决了一个 🚨
**选 A（加只读副本）→ 正确 C（迁移 Aurora）**
① 故障转移 60–120 秒 → 30 秒内　② 报表读分流
**只读副本只解决 ②，对故障转移时间毫无帮助。**
> 🚨 **「漏掉后半句限定条件」第 4 次**（前三次：错题 1 / 12 / 15）

### 错题 19｜Q11：EBS Multi-Attach 的硬限制
**选 A（EBS Multi-Attach）→ 正确 B（EFS）**

| Multi-Attach 限制 | 题干要求 |
|---|---|
| 只能**单个可用区内** | 3 个可用区 ❌ |
| 最多 16 台 | 20 台 ❌ |
| 需集群感知文件系统 | 标准 POSIX ❌ |
| 容量固定 | 自动扩展 ❌ |

**四条全部违反。**

### 错题 20｜Q13：S3 本来就是多 AZ 的
**选 B（启用多可用区冗余）→ 正确 A（CRR + Origin Failover）**
S3 **本来就是** Region 内多 AZ 冗余，这不是可「启用」的选项。
题干说「**整个 AWS 区域**发生故障」→ **跨区问题只能跨区解决**。

### 错题 21｜Q15：题干已经替你排除了错误选项
**选 C（RDS Proxy）→ 正确 D（Provisioned Concurrency）**
题干两句排除线索：「都发生在**新的执行环境初始化时**」（= 冷启动）、
「**与数据库查询耗时无关**」（= 已排除数据库方向）。RDS Proxy 解决连接池耗尽，不是冷启动。
> 附：B 选项「API GW 超时提高到 60 秒」**本身不成立** —— 29 秒是硬上限。

### 错题 22｜Q17：DAX 是缓存，不是复制
**选 D（DAX）→ 正确 A（Global Tables）**
DAX 不能做跨区双向同步，也没有冲突解决。**多区域双写 = Global Tables，唯一答案。**

### 错题 23｜Q22：Spectrum 没动成本根源
**选 C（Redshift Spectrum）→ 正确 B（Athena + 下线 Redshift）**
Spectrum 确实能查 S3，**但它依然要求 Redshift 集群 7×24 开着**。
题干痛点正是「集群成本与『每月几次』的使用频率不匹配」→ 选 C 等于没解决问题。
> 「**对了一半**」模式：前半句对（要查 S3），结论错（没动成本根源）。

## ✅ 换机制：把「注意力」改成「验证」

> **选出答案后，不要立刻进入下一题。**
> **回到题干，找出每一句带要求的话，逐句问：「我选的这个，满足这句吗？」**

用 Q23 走一遍：
```
选了 Pilot Light
  → 回读要求句①「RTO 4 小时」                    满足 ✓
  → 回读要求句②「RPO 1 小时」                    满足 ✓
  → 回读要求句③「不接受第二区域长期运行任何计算资源」 ✗ ← 这里就停住了
```

**这 8 道里 Q23、Q30、Q35、Q36 四道会在这一步被拦下 → 18/22（82%）**

**为什么这个更可靠**：「圈约束词」要求在**输入阶段**维持高注意力；
「回读验证」是在**输出后**做一次**机械检查**，不依赖状态。

## 逐题错因（错题 24–31）

### 错题 24｜Q23：Pilot Light 违反了明写的约束
**选 C → 正确 D（Backup & Restore）**
题干原话「**不接受在第二区域长期运行任何计算资源**」。
Pilot Light 的定义就是常驻数据库副本 → 直接违反。

### 错题 25｜Q24：安全组管不到 S3
**选 D → 正确 C（Gateway Endpoint + `aws:SourceVpce` 桶策略）**
SG 只能控制「谁能连上 Endpoint」，拦不住持合法 IAM 凭证的人从互联网访问桶。
题干「即使拥有完全正确的 S3 权限也必须拒绝」→ **拒绝动作必须写在桶策略里**。

### 错题 26｜Q30：阻止 ≠ 检测 🚨
**选 C（Config 检测告警）→ 正确 D（SCP）**
题干「**都不能停用**」= 阻止。Config 是事后检测。
> 🚨 **同场 Q39 答对了完全相同的辨析**（Block Public Access 预防 vs Config 检测）

### 错题 27｜Q31：GSI 给不了 SQL 灵活性
**选 C（GSI）→ 正确 B（导出 S3 + Athena）**
GSI 只优化**预先设计好的**访问模式，分析师的临时报表查询是多变的；
且题干要「**SQL 式的灵活查询能力**」，GSI 给不了 SQL。

### 错题 28｜Q32：Cooldown ≠ 优雅关闭
**选 D（延长冷却时间）→ 正确 A（生命周期挂钩）**
**Cooldown 控制「多久之后允许下一次扩缩」，不是「终止前等一等」。**
优雅关闭 = **Lifecycle Hook（Terminating:Wait）**

### 错题 29｜Q35：错题 1 原题重现 🚨
**选 A（快照恢复到原实例）→ 正确 D（PITR 到新实例）**
两句限定：「恢复到删除前**约 5 分钟**」（快照粒度做不到，必须 PITR）
+「数据库**仍在正常服务其他业务，不能中断**」（恢复到原实例 = 中断）
> 🚨 **错题 1 的结论原样适用**：出现「不影响现有库」→ 排除原地恢复，选 PITR 到新实例

### 错题 30｜Q36：access key 就是长期凭证 🚨
**选 D（IAM 用户 + 轮换 access key）→ 正确 A（IAM Role）**
题干原话「**不得存储任何长期凭证**」。access key **就是**长期凭证。
> 🚨 KMS 测验 Q7 答对过，且当时识破了更狡猾的「存 Parameter Store」诱饵

### 错题 31｜Q37：错题 6 原样重现 🚨
**选 B（Transfer Acceleration）→ 正确 D（CloudFront + Lambda@Edge）**
**Transfer Acceleration 加速的是【上传到 S3】**，既不降低 EC2 CPU，也不加速下行分发。
