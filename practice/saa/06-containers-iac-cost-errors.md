## 📌 两层角色按时间先后记

```
Task Execution Role = 【启动容器之前】ECS 代理需要的权限（拉 ECR 镜像、建日志流）
Task Role           = 【容器跑起来之后】你的代码需要的权限（读 S3、写 DynamoDB）
```

> Execution 在前（准备阶段），Task 在后（运行阶段）。
> 题干说「**容器内的应用**要访问 XX」→ 一定是 **Task Role**。

## 📌 ECS vs EKS 的分界线不是规模

「大规模必须用 EKS」是流传很广的误解。ECS 支撑着极大规模的生产负载。
**分界线只有一个：Kubernetes 生态（kubectl / Helm / 多云 / 现有 K8s 迁移）。**

## 📌 Fargate vs EC2 模式：只有三个信号选 EC2

1. 需要 **GPU**
2. 需要**特定实例类型**（如超大内存）
3. 要用 **Spot** 大幅降本

**看不到这三个，就选 Fargate。**

## ⚠️ 反向题统计（已出现 4 次）

考场 65 题里大概会碰到 **3–6 道**「下列错误的是 / 以下哪项不是 / 除了」，每道约值 15 分。
> **习惯：看到「错误」「不是」「除了」就在心里标红，答完回头确认方向没反。**

## ✅ Q7 是「双约束」题的正确处理示范

**这正是我最顽固失分点（错题 1/12/15）的形态，这次处理对了。**

| 约束 | 能满足的选项 |
|---|---|
| 「可能更换实例类型」 | Convertible RI ✅、Compute SP ✅（Standard RI ❌、EC2 Instance SP ❌） |
| 「覆盖 Lambda 和 Fargate」 | **只有 Compute SP** ✅ |

> 第一个约束砍掉两个，第二个约束砍掉剩下的一个。
> **只看第一条的话，B 和 C 都像对的。两条都核对才能到唯一答案。**

## 📌 Q12：不用记死数字，记「同一档」
